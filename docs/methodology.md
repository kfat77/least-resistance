# 方法论：最小阻力

## 1. 核心假设

系统只回答一个问题：**接下来 15 分钟，价格向上扫荡还是向下扫荡更省力？**

「最小阻力」在这里被具体化为**流动性扫荡**：价格会朝可成交流动性更厚的一侧移动。
厚流动性不是墙，而是目标——那里有更多对手盘可以成交，价格过去时遇到的摩擦更小。
在此之上再叠加三类证据：谁在主动付出价差、谁在真实吸收、哪一侧更空。

这套假设不是确定性规律，而是可被滚动结算检验的模型。系统每 60 秒记录一次方向，
15 分钟后按真实价格结算，长期比较命中率与 Brier 分数，而不是只展示当前判断。

## 2. 五类证据

### 2.1 流动性扫荡（sweep，权重 0.68）

把中间价上下 ±3% 内所有「可被扫掉」的流动性按距离衰减加权。来源有四个：

- 盘口挂单：96 个价格桶的 bid/ask 名义金额；
- 冰山隐藏量：`hidden_usd = 当前显示量 × 推断倍数`；
- 模型估算清算池：按 5m 成交分布 × 杠杆分布反推的清算价；
- 已实现清算：交易所 `forceOrder` 成交按价格归因。

每个池按距离衰减：

```
weight = exp(-distance / 1.2%)
```

四个来源先各自归一化上下侧占比，再按 `0.45 / 0.15 / 0.25 / 0.15`
（盘口 / 冰山 / 估算清算 / 已实现清算）混合，避免估算清算图的美元金额淹没盘口。
扫荡分为：

```
raw_score = (above_weight - below_weight) / (above_weight + below_weight)
conviction = min(1, (盘口 + 冰山加权金额) / 该币阈值)   # BTC $8M / ETH $3M
sweep_score = tanh(2.5 × raw_score) × conviction
```

`score > 0` 表示上方可扫荡流动性更厚，价格倾向向上扫穿；`< 0` 表示下方更厚。
`conviction` 是样本充足度：近端流动性太薄时，不因为几笔小单就给出极端分数。

返回给前端的字段包括：`above_usd` / `below_usd`（仅盘口+冰山实际深度）、
`model_above_usd` / `model_below_usd`、`conviction`、`target`、`pools`
（按加权金额排序，最多 12 个）与各来源覆盖金额。前端左栏「流动性扫荡」卡与
信号明细直接使用这些字段。

### 2.2 墙/冰山吸收（absorption，权重 0.08）

墙的定义不是「绝对大单」，而是相对当前盘口显著异常的单档：

```
threshold = max(该币最小墙金额, 9 × 扫描范围内单档中位数)
```

在 ±1.5% 内、每边最多取 5 面。墙的静态大小已经计入 2.1 的扫荡池，若在这里
再按大小计分，等于把同一批挂单算两遍。因此本信号只统计这些价位**真实吸收**的
主动成交：

```
absorbed = 该价位近 120 秒主动成交中与挂单方向相反的名义金额
refill_bonus = 1 + 0.15 × min(回补次数, 6)
strength = absorbed × refill_bonus / (1 + 220 × distance)
conviction = min(1, (bid_strength + ask_strength) / 该币阈值)
absorption_score = clamp((bid_strength - ask_strength) / (bid_strength + ask_strength) × conviction)
```

买侧吸收越多，说明有人愿意在该价位持续接货，分数越正；卖侧吸收越多则越负。
没有吸收时该分量为 0，而不是凭挂单大小猜方向。默认采用 `barrier` 解读；
`magnet` 解读把该分量取反，二者在同一份行情上并行记账（见 6.1）。

每面墙跟踪首次出现时间、峰值数量、当前数量、回补次数与累计消失量，用于判断
它是真实承接还是虚假挂单（见 2.3 与 7.3）；撤单后才从阻力中移除。

### 2.3 冰山（icebergs）

冰山是「显示量很小、实际持续吸收」的挂单。系统用两个证据推断：

- **吸收量**：该精确价位上，近 120 秒主动成交中与挂单方向相反的部分累计金额；
- **回补次数**：单档数量在短窗口内被吃掉后又快速补回（掉量后 3.5 秒内补回
  至少 25% 的掉量，记一次回补）。

入选条件（同时满足）：

```
显示金额 ≥ $15,000
存在时间 ≤ 900 秒
吸收金额 ≥ 该币冰山最小金额（BTC $250k / ETH $90k）
且（回补次数 ≥ 2 或 吸收/显示 ≥ 1.6）
```

按 `吸收金额 × (1 + 0.2 × min(回补次数, 6))` 排序取前 6。冰山越靠近中间价，
对方向的含义越强。它的 `hidden_usd`（隐藏总量）进入 2.1 的扫荡池，它的
`absorbed_usd`（真实吸收）进入 2.2 的吸收分——两个量不同，不会重复计分；
冰山本身不单独占权重项。

### 2.4 清算：估算池 + 已实现流

**估算清算池**（进入 2.1 扫荡分）：当数据源收不到真实强平时，用 5 分钟 K 线的
成交分布 × 杠杆分布反推：

```
多头爆仓价 ≈ entry × (1 - 1/L + maintenance_margin)
空头爆仓价 ≈ entry × (1 + 1/L - maintenance_margin)
```

杠杆分布为 `5x 10% / 10x 20% / 20x 22% / 25x 18% / 50x 20% / 100x 10%`，
维持保证金率 0.5%，估算带限制在距中间价 ±6% 内。**估算不是实际强平**，页面
用不同颜色与文案分开标注。

**已实现清算流**（liquidations，权重 0.05）：统计近 5 分钟 `forceOrder` 成交
的方向与金额：

```
liq_flow_score = (short_liquidation_usd - long_liquidation_usd) / 两者之和
```

空头被强平 = 强制买入 = 向上压力；多头被强平 = 强制卖出 = 向下压力。窗口内
没有真实强平时该分量为 0，并在信号明细里明确写出来，而不是把估算伪装成实际。

### 2.5 主动成交流（flow，权重 0.14）

统计近 5 分钟主动买（吃卖单）与主动卖（吃买单）的名义金额：

```
flow_score = (buy_usd - sell_usd) / (buy_usd + sell_usd)
```

同时维护 10 秒桶的累计成交量差（CVD，90 个点）与大单逐笔列表。CVD 的斜率
比单点数值更能说明谁在持续付出价差。

### 2.6 流动性真空（vacuum，权重 0.05）

比较中间价上下 1.5%–3% 走廊的挂单密度（每 1% 距离的名义金额）：

```
vacuum_score = (down_density - up_density) / (up_density + down_density)
```

`score` 为正表示下方挂单相对更厚、上方相对更薄，价格向上滑的阻力更小；
为负则说明上方厚、下方薄。该信号刻意避开 2.1 的近端扫荡池与 2.2 扫描的
±1.5%，只读外侧走廊，捕捉「没有墙挡着」的情况。

## 3. 合成方向分数

```
score = Σ (signal_score × weight)          # 权重见上，总和 1.0
p_up  = sigmoid(2.4 × score)               # 映射为上行概率
```

当前权重：`sweep 0.68 / flow 0.14 / absorption 0.08 / liquidations 0.05 /
vacuum 0.05`。`score > +0.07` 判为上行，`score < -0.07` 判为下行，否则中性。
置信度取 `max(p_up, 1 - p_up)`，保证中性判断也有一个诚实的概率表达。

五个分量使用不同证据与不同价格尺度：扫荡分读全深度流动性池，吸收读真实成交，
清算流读已实现强平，主动流读逐笔方向，真空只读外侧走廊。估算清算只进入扫荡分，
与已实现清算流分开，避免把同一批强平算两遍。

## 4. 目标位与失效位

非中性时，在预测方向 `+0.08% ~ +1.2%`（下行同理取负）范围内寻找候选：

- **最厚的扫荡池**（优先，来源为盘口/冰山等可真实成交的流动性）；
- 该方向的估算/真实清算带；
- 该方向的墙；
- 已发生的清算密集区。

排序时扫荡池优先，其次按「距中间价近、金额大」；取前 3 个作为 `levels`，
第一个作为 `target_price`。失效位取反方向最近一面墙（距离 ≥0.05%）；没有墙时
用 `mid × (1 ∓ 0.45%)` 作为经验失效位。目标与失效位都只是结构参考，不是交易指令。

## 5. 摩擦曲线

从中间价向两侧各取 3%、24 个等距桶，累计计算「吃掉多少名义金额才能把价格
推到该距离」。两条曲线的斜率差就是最直观的阻力不对称：上升曲线更平缓的一侧
更容易被推动。前端的摩擦曲线图直接使用 `friction` 数组。

## 6. 预测账本与评估

- 每 ≥60 秒记录一次预测：时间、价格、方向、p_up、score、置信度、结算时间；
- 15 分钟后用当时价格结算：方向命中记 1，否则 0，同时记录涨跌幅；
- 中性预测不计入方向命中率，但保留在账本中；
- 页面展示样本数、命中率、Brier 分数与待结算数量。

Brier 分数使用 `(p_up - outcome)²`，越低越好；它同时惩罚过度自信与方向错误。
样本少时数字不可靠，因此 UI 会显示 pending 与样本数，而不是只显示一个百分比。

### 6.1 墙模式 A/B（WALL_MODE）

墙的方向含义存在两种互斥假设，系统不靠主观偏好选边：

- `barrier`：买墙承接主动卖单，是下行障碍；卖墙压制反弹，是上行障碍。买侧吸收
  使 `absorption_score` 为正。
- `magnet`：大额挂单是流动性磁吸位，买墙把价格往下吸、卖墙往上吸。买侧吸收使
  `absorption_score` 为负，即 `absorption_magnet = -absorption_barrier`。

同一次快照会分别计算两套分量：`WALL_MODE` 指定当前展示模式，另一种模式作为
影子账本写入独立文件。两本账都按 60 秒记录、15 分钟结算，因此比较的是同一段
行情、同一价格序列下的方向命中率与 Brier。服务端每 2 秒在后台生成快照推进账本
（`LEDGER_TICK_S`），即使无人打开页面，样本也会继续积累。

- 实验起点 `model.ab_started` 之后记录的样本才计入 A/B（历史账本不污染对照）；
- 页面顶栏「墙模式 WALL」分段控件可随时切换当前展示模式；本地站调用
  `POST /api/wall-mode` 并写入 `data/<mode>/wall_mode.txt`，静态站在 Worker 内
  切换并用 `localStorage` 记住选择；显式 `WALL_MODE` 环境变量仍优先；
- `accuracy_ab` 与 `accuracy_alt_ab` 分别给出现行模式与影子模式的
  `samples / hits / hit_rate / brier / pending`；
- 决策规则：两种模式各至少 20 条已结算窗口（Brier 对全部已结算窗口计算，方向命
  中率作为辅助指标），且一方 Brier 至少低 0.02、命中率不更差时，该模式成为默认
  值；否则保留 `barrier`，避免小样本噪声导致来回切换；
- 目标位、失效位与叙述仍按当前展示模式生成；A/B 只比较可结算的
  `direction / p_up`，不让目标位逻辑影响胜负。

运行 `python scripts/compare_wall_modes.py` 可直接读取上述字段并打印判定结果。

## 7. 已知局限

1. **深度快照有限**：REST 快照只取 1000 档，远价档位可能不完整；分析只使用
   ±3% 内的档位，避免被异常远价干扰。
2. **真实强平可能缺失**：部分网络环境收不到 `!forceOrder`，此时已实现清算流为 0，
   扫荡池里的清算部分是模型估算；页面必须明确区分两者。
3. **撤单/冰山是推断**：墙消失且成交很少会被标记为 spoof，但撤单与「被吃穿后
   重新挂回」在数据上可能相似；冰山也是概率推断，不是交易所披露的订单类型。
4. **模拟模式是合成数据**：`sim` 用于离线演示与视觉验收，不代表真实市场统计特征。
5. **延迟与竞争**：WS 增量、REST 轮询与浏览器推送都有延迟；高频参与者看到的
   盘口与这里不同。
6. **不是投资建议**：任何方向判断都可能失效，清算地图与目标位只是结构参考。
