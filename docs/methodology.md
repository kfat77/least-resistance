# 方法论：最小阻力

## 1. 核心假设

系统只回答一个问题：**接下来一段时间，价格向上走和向下走，哪边更省力？**

「省力」被拆成两类可观测事实：

1. **摩擦力不对称**：某一侧挂单更厚、墙更大、被吃掉的隐藏量更多，价格穿过该侧需要更多资金。
2. **燃料不对称**：某一侧堆积了更多会被触发的止损/清算，价格一旦靠近就会加速。

两者合起来就是「阻力」。价格倾向于沿着阻力更小的一侧移动。这是对市场微结构的
一种近似，不是确定性规律；因此系统必须用滚动结算来检验自己，而不是只给出判断。

## 2. 五类证据

### 2.1 挂单堆积（book，权重 0.30）

按距中间价 ±0.25%、0.5%、1%、2%、3% 五个带统计买卖两侧的累计名义金额，
并计算每个带的失衡：

```
imbalance = (bid_usd - ask_usd) / (bid_usd + ask_usd)
```

综合分取近端两带加权：

```
book_score = 0.45 × imbalance(0.5%) + 0.55 × imbalance(1%)
```

近端权重更高，因为 2% 以外的挂单短期难以影响价格。此外用 96 个价格桶、
±3% 范围的挂单剖面（profile）展示堆积形态，前端据此画出深度山形图。

### 2.2 墙（walls，权重 0.24）

墙的定义不是「绝对大单」，而是相对当前盘口显著异常的单档：

```
threshold = max(该币最小墙金额, 9 × 扫描范围内单档中位数)
```

在 ±1.5% 内、每边最多取 5 面、按名义金额与距离排序。墙的阻力按距离衰减：

```
strength = usd / (1 + 220 × distance)
wall_score = (bid_block - ask_block) / (bid_block + ask_block)
```

`bid_block` 是下方买墙总强度（支撑/向上阻力），`ask_block` 是上方卖墙总强度
（压制/向下阻力）。买墙越厚，score 越正。

每面墙跟踪首次出现时间、峰值数量、当前数量、回补次数与累计消失量，用于判断
它是真实承接还是虚假挂单（见 2.3 与 7.3）。

### 2.3 冰山（icebergs）

冰山是「显示量很小、实际持续吸收」的挂单。系统用两个证据推断：

- **吸收量**：该精确价位上，近 120 秒主动成交中与挂单方向相反的部分累计金额；
- **回补次数**：单档数量在短窗口内被吃掉后又快速补回（掉量后 3.5 秒内补回
  至少 25% 的掉量，记一次回补）。

入选条件（同时满足）：

```
显示金额 ≥ $15,000
存在时间 ≤ 900 秒
吸收金额 ≥ 该币冰山最小金额（BTC $250k / ETH $90k）
且（回补次数 ≥ 2 或 吸收/显示 ≥ 1.6）
```

按 `吸收金额 × (1 + 0.2 × min(回补次数, 6))` 排序取前 6。冰山越靠近中间价，
对方向的含义越强；它代表「有人愿意在这个价位持续成交但不暴露总量」。

### 2.4 清算（liquidations，权重 0.22）

真实强平来自 `!forceOrder` 流，保留 24 小时，并按 ±4% 的价格桶聚成簇。清算簇
是磁吸位：价格靠近时，被强平的单子会以市价成交，进一步推动价格。

当数据源收不到真实强平时，系统用 5 分钟 K 线的成交分布 × 杠杆分布反推估算：

```
多头爆仓价 ≈ entry × (1 - 1/L + maintenance_margin)
空头爆仓价 ≈ entry × (1 + 1/L - maintenance_margin)
```

杠杆分布为 `5x 10% / 10x 20% / 20x 22% / 25x 18% / 50x 20% / 100x 10%`，
维持保证金率 0.5%。估算带限制在距中间价 ±6% 内。**估算不是实际强平**，页面
用不同颜色与文案分开标注。

清算压力同样按距离衰减（3% 以外为 0），并对真实簇乘 0.35 的保守系数：

```
liq_score = (上方空头清算强度 - 下方多头清算强度) / 两者之和
```

上方空头清算越多，score 越正（向上磁吸）。

### 2.5 主动成交流（flow，权重 0.14）

统计近 5 分钟主动买（吃卖单）与主动卖（吃买单）的名义金额：

```
flow_score = (buy_usd - sell_usd) / (buy_usd + sell_usd)
```

同时维护 10 秒桶的累计成交量差（CVD，90 个点）与大单逐笔列表。CVD 的斜率
比单点数值更能说明谁在持续付出价差。

### 2.6 流动性真空（vacuum，权重 0.10）

比较中间价上下 0.5%–2% 走廊的挂单密度（每 1% 距离的名义金额）：

```
vacuum_score = (down_density - up_density) / (up_density + down_density)
```

`score` 为正表示下方挂单相对更厚、上方相对更薄，价格向上滑的阻力更小；
为负则说明上方厚、下方薄。该信号捕捉「没有墙挡着」的情况，与 2.2 互补。

## 3. 合成方向分数

```
score = Σ (signal_score × weight)          # 权重见上，总和 1.0
p_up  = sigmoid(2.4 × score)               # 映射为上行概率
```

`score > +0.07` 判为上行，`score < -0.07` 判为下行，否则中性。置信度取
`max(p_up, 1 - p_up)`。这保证中性判断也有一个诚实的概率表达。

## 4. 目标位与失效位

非中性时，在预测方向 `+0.08% ~ +1.2%`（下行同理取负）范围内寻找候选磁吸位：

- 估算/真实清算带中该方向的清算金额；
- 该方向的墙；
- 已发生的清算密集区。

按「距中间价最近、金额更大」排序，取前 3 个作为 `levels`，第一个作为
`target_price`。失效位取反方向最近一面墙（距离 ≥0.05%）；没有墙时用
`mid × (1 ∓ 0.45%)` 作为经验失效位。目标与失效位都只是结构参考，不是交易指令。

## 5. 摩擦曲线

从中间价向两侧各取 3%、24 个等距桶，累计计算「吃掉多少名义金额才能把价格
推到该距离」。两条曲线的斜率差就是最直观的阻力不对称：上升曲线更平缓的一侧
更容易被推动。前端的摩擦曲线图直接使用 `friction` 数组。

## 6. 预测账本与评估

- 每 ≥60 秒记录一次预测：时间、价格、方向、p_up、score、置信度、结算时间；
- 15 分钟后用当时价格结算：方向命中记 1，否则 0，同时记录涨跌幅；
- 中性预测不计入方向命中率，但保留在账本中；
- 页面展示样本数、命中率、Brier 分数与待结算数量。

Brier 分数使用 `(p_up - outcome)²`，越低越好；它同时惩罚过度自信与方向错误。
样本少时数字不可靠，因此 UI 会显示 pending 与样本数，而不是只显示一个百分比。

## 7. 已知局限

1. **深度快照有限**：REST 快照只取 1000 档，远价档位可能不完整；分析只使用
   ±3% 内的档位，避免被异常远价干扰。
2. **真实强平可能缺失**：部分网络环境收不到 `!forceOrder`，此时真实强平为 0，
   页面必须明确区分「实际强平」与「模型估算」。
3. **撤单/冰山是推断**：墙消失且成交很少会被标记为 spoof，但撤单与「被吃穿后
   重新挂回」在数据上可能相似；冰山也是概率推断，不是交易所披露的订单类型。
4. **模拟模式是合成数据**：`sim` 用于离线演示与视觉验收，不代表真实市场统计特征。
5. **延迟与竞争**：WS 增量、REST 轮询与浏览器推送都有延迟；高频参与者看到的
   盘口与这里不同。
6. **不是投资建议**：任何方向判断都可能失效，清算地图与目标位只是结构参考。
